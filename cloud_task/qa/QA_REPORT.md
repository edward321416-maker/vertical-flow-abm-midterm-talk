## 1. γ=0 표현 정정

γ=0은 목적지 효용의 앵커 비중항 γ·x_j만 0인 조건이다. 도착, 층 선택, 이동 저항, 체류, 퇴장 규칙은 그대로 작동한다(수정 논문 4.1절). 「프로그램 유인이 없을 때」는 프로그램 자체나 모든 유인이 없다는 뜻으로 읽힐 수 있어 고쳤다.

| 쪽 | 이전 | 수정 |
|---|---|---|
| 6 | 프로그램 유인이 없을 때, 위층으로 갈수록 상행유량은 어떻게 줄어드는가? / 유인 계수 γ = 0 · U와 국소 AUFR | **추가 앵커 유인이 없을 때**, 위층으로 갈수록 상행유량은 어떻게 줄어드는가? / γ = 0 (앵커 비중 효용항이 0) · U와 국소 AUFR |
| 8 | 연속형 · γ=0 · 200회 평균 | 연속형 · 추가 앵커 유인 없음(γ=0) · 200회 평균 |
| 10 제목 | 추가 유인이 없는 조건에서도 … | **추가 앵커 유인이 없는 조건**에서도 상행유량은 위로 갈수록 줄었다 |
| 10 부제 | 유인 계수 γ = 0 · … | 추가 앵커 유인이 없는 조건(γ = 0) · … |
| 10 주석 | (없음) | 「γ = 0은 앵커 비중 효용항만 0으로 둔 조건이다. 도착·층 선택·이동 저항·체류·퇴장 규칙은 그대로이므로 이동 마찰만의 자연 상태가 아니다.」 추가 |
| 11 부제 | 유인 계수 γ = 0 · … 반복 분포의 2.5–97.5% 구간 | 추가 앵커 유인이 없는 조건(γ = 0) · … 200회 반복값의 2.5–97.5 백분위 구간(음영) |
| 18 | 연속형 γ=0에서 … | 추가 앵커 유인이 없는 연속형(γ=0)에서 … |

자동 검사: PDF 전체 텍스트에서 「앵커」 없이 쓰인 「유인이 없」은 0건이다. 「추가 앵커 유인이 없」은 5개 쪽에 있다.

## 2. 절대경로 제거와 재생성

- `build.py`: 저장소 루트를 `Path(__file__).resolve().parents[1]`로 찾는다. CSV는 `analysis/outputs/aik/`, 기본 출력은 `cloud_task/output/vertical_flow_midterm_refined.pdf`이다. 인자 없이 실행해도 된다.
- `lib.py`: 글꼴 경로를 고정하지 않는다. `$VF_FONT_DIR` → `cloud_task/fonts/` → Linux/macOS/Windows 시스템 글꼴 폴더 → `fc-list` 순서로 찾는다. 찾지 못하면 설치 방법을 담은 오류를 낸다.
- 의존성: `cloud_task/src/requirements.txt`.
- `grep -rn "/home/user" cloud_task/src cloud_task/qa` 결과는 0건이다.

재생성 검증:
1. 저장소의 추적 파일만 임시 폴더에 복사했다. 작업 디렉터리를 `/`로 두고 `VF_FONT_DIR=<임시 글꼴 폴더> python3 -I <복사본>/cloud_task/src/build.py`를 실행했다. 18쪽이 생성됐고, 원본 결과와 `pdftotext` 텍스트가 완전히 같았다.
2. 커밋·푸시 후 원격 브랜치를 새로 clone해 같은 검증을 반복했다. 결과는 PR 본문에 적는다.

```
python3 cloud_task/src/build.py            # PDF + title_inventory.csv

```

## 4. 배치·글꼴 검증 (`qa/layout_check.py` → `qa/layout_check.csv`)

**132개 검사, 실패 0.**

- **글꼴:** 6개 모두 임베드되어 있다. NanumBarunGothic Regular/Bold, DejaVu Sans Regular/Bold, 서브셋 포함.
  - 이전 판에 있던 미임베드 Helvetica 기본 글꼴 항목은 제거했다(`initialFontName`).
  - DejaVu Sans는 γ·Δ, `<`·`>`, `−`(U+2212)에만 쓴다. 나눔바른고딕의 γ는 r처럼 보이고, `<`는 꺾쇠처럼 보이며, U+2212 글리프는 없다.
- **텍스트 레이어의 음수 부호:** 이전 판은 마이너스를 선으로 그려서 검색·복사 시 부호가 빠졌다(「−4.1」 → 「4.1」). 지금은 실제 글리프를 쓰고, 검사로 부호가 남는지 확인한다.
- **영역:**
  - 모든 텍스트와 그래픽이 16pt 안전 여백 안에 있다.
  - 텍스트·선·막대가 좌우 56pt 본문 여백(±4pt)을 벗어나지 않는다. 이 검사로 9쪽 E2 격자와 10쪽 y축 제목이 여백을 넘던 문제를 찾아 고쳤다.
- **겹침:** 텍스트 객체끼리 겹침 0건. 검출기는 일부러 겹치게 만든 대조 PDF에서 겹침과 여백 이탈을 모두 잡는 것을 확인했다.
- **글자 크기:**
  - 본문 최소 10pt. 예외는 6쪽 RQ 번호 9.5pt다.
  - 10pt 미만 텍스트는 모두 아래첨자(본 글자의 0.66배, 6.9–8.2pt)다.
- **색:**
  - 모든 쪽 배경이 흰색이다.
  - 텍스트만 있는 쪽(1·2·4·5·6·17·18)의 유채색 픽셀은 0%다.
  - 색은 3·9–16쪽 데이터 그래픽에만 쓴다.
- **렌더:** 150dpi 개별 렌더 18장과 접촉 시트 `qa/renders/contact_sheet.png`.

## 6. 남은 한계

- **외부 레퍼런스:** 지정 사이트 6곳을 여는 데 두 번 실패했다(네트워크 정책). 검색 요약만 참고했고, 근거는 수정 논문과 저장소의 기획 자료다(`references_review.md`). 「실제 열람 4+4건」 요구는 충족하지 못했다.
- **모델 상태:** 세션의 모델·effort·크레딧 상태는 이 보고서에서 확인하지 않았다. Modal은 사용하지 않았다.
- **회귀 재추정 범위:** 승수(θ)와 잠식률의 점추정만 재추정했다. 군집-강건 CI, 부트스트랩 CI, 준포아송 deviance 감소율은 CSV 값을 그대로 썼다.
- **en dash 간격:** 나눔바른고딕의 en dash(–)는 좌우 여백이 넓어 「3 – 4」처럼 보인다. 판독에는 문제가 없어 유지했다.
- **9쪽 빈 공간:** 두 실험 격자 아래에 여백이 남는다. 내용을 늘리지 않으려고 그대로 두었다.
